# Power User Hub Community Knowledge

Power User Hub is designed to learn Android settings and services from real devices rather than ship a permanently frozen tweak list.

## How the database works

`catalog-v1.json` is the curated runtime catalog consumed by released builds. Findings are device/build-specific evidence, not universal claims. A service or setting can therefore have different observations on different OEMs, Android versions, and firmware fingerprints.

The app creates a JSON finding that includes the raw key/component, human-readable terminology, observed values or service events, Android version, device model, and build fingerprint. Users submit that record through the repository's `community-finding` issue flow. Findings are reviewed before being promoted into the runtime catalog.

Community submissions are never executed as shell commands. The catalog can describe known values, effects, risks, and observed behavior, but privileged operations remain generated by reviewed Power User Hub code.

## Confidence

- `Unknown`: no useful evidence yet.
- `Inferred`: terminology is inferred from the raw name only.
- `Observed`: at least one device produced repeatable runtime evidence.
- `Probable`: an effect has repeated enough to be useful but is still described as correlation unless causation is independently verified.
- `Verified`: reserved for reviewed documentation or strong controlled evidence.

## Contributions

Submit the JSON generated by Power User Hub. Include what you changed, what happened, whether the value persisted, and any rollback information. Do not remove the device/build metadata because an OxygenOS result is not automatically a Samsung, Pixel, or AOSP result.
